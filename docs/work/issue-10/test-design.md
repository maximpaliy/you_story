Keep Python/PostgreSQL/dependency pins from the foundation. Pin browser engine,
runner, cryptographic dependencies and test generators in reviewed lock files
before execution; record resolved versions with evidence. Synthetic test keys
are generated by fixture setup and never become deployment defaults. Only
loopback HTTPS provider transports may be substituted by test composition;
production endpoints remain fixed Google HTTPS allowlists. No live Google
account, live invitation or production credential is needed.

Reuse the guarded `you_story_issue9_test` disposable database and marker. Runtime
tests reconnect as `app_runtime`; superuser/owner only seed synthetic fixtures,
inspect committed state and execute explicitly labelled adversarial DDL mutations.
Do not run destructive suites concurrently against this database. No SQLite,
unmarked database, owner-as-runtime fallback, skip-on-missing-DB or unbounded
external provider call is acceptable evidence.

Reuse `tests/auth_support.py` and its owner-only restore-checked `_auth_now()`
fixture for exact database boundary instants. Production 005 samples real
clock_timestamp after advisory/row lock waits; never replace that with stable
transaction-start time. Retain the existing real-clock lock-wait tests and add
adapter/public-port tests proving the clock primitive and wrappers are preserved.
No caller time, runtime-executable clock helper, new SQL overload or application
clock-bypass endpoint is added. Provider NumericDate tests use supported test
composition clock injection and independently exercise the real-clock default.

## Fixtures and state oracles

A/B are distinct users/personal tenants, with two A devices and one B device.
Include unknown subject, preallowlisted subject, existing active identity and
separate disabled identity/user/tenant states. Invitations include valid,
expired-at-equality, consumed-by-same/different-subject and wrong-issuer tokens.
Tenants include `catalog_pending` and `ready`. X/Y browser contexts have independent
binders; X tabs share one binder. Include pending/claimed/succeeded/failed/expired
transactions, 9/10/11 session boundaries and rate/capacity boundaries.

Every positive case asserts exact permitted result fields, actual later
authenticated request and exact committed identity/tenant/session/catalog/grant
state. Every denial snapshots all touched tables before and after, including
versions and counters. Permitted counter/claim/terminalization writes are listed
per case; they cannot conceal identity creation, invitation consumption, session
replacement or catalog writes. Return-shape canaries in inaccessible fields
prove absence from responses; status-only assertions are insufficient.

Use test barriers around claim, exchange, finish, session resolution/revocation,
catalog ensure and ready marking. Exercise both serialization orders and inspect
committed state; sleeps or a single lucky schedule are insufficient. Snapshot
inspection uses separate committed transactions, not the failing transaction's
uncommitted connection.

Fault injection after every identity creation, invitation consumption, user-limit
consume, session insert and success terminalization step must roll the entire
finish transaction back. Separately committed claim remains consumed and failed
terminalization is permitted afterward. Callback cookie is emitted only after
commit. Simulate lost post-commit HTTP response: no raw-token recovery or second
session issuance for that binder; unrelated bearerless orphan grants no access.

## Browser, API and actor coverage

Apply WEB-01–05 to every introduced surface: `GET /login`,
`POST /auth/google/start`, `GET /auth/google/callback`, `GET /`, `GET /profile`,
`GET /api/v1/profile`, and `POST /logout`, plus existing health and unknown/error
routes under the outer response policy. This path set is the proposed API under
review; its acceptance belongs to the lead's concrete API contract. No additional
JSON mutation route is inferred. JSON profile cannot expose CSRF/session/token,
provider subject/issuer, email, invitation, binder, or internal control details.
Health routes remain anonymous and must not touch an ambient session.

WEB-01 uses ADR-011's accepted HKDF generation; stale independent-random wording
in the older WEB design is superseded. Expand correct/missing/duplicate/header+
field/foreign/rotated/expired proof cases on actual unsafe routes. Route-specific
token transport is fixed, never guessed from content. WEB-02 generates full
token-validity x origin/fallback x Fetch Metadata x declared representation
combinations, with duplicate raw ASGI headers, stream overrun and Content-Length
mismatch. Domain dispatch probes assert zero downstream call on policy rejection.

WEB-03 seeds stored canaries in provider/control/preference fixture values and
asserts they remain absent from home/profile/JSON: this slice selects no
user-controlled presentation text. Inject reflected query/form/provider-error
canaries (normalized Unicode, closing tags, quotes, SVG/MathML and entities) and
assert rejection or unreflected generic response, with no added DOM nodes,
attributes, script execution, beacon or navigation. No provider image URL is
fetched. Exercise the actual autoescaping template engine using a test-only
presentation fixture and disable escaping in a test-only template mutation;
the detector must catch it. That is a rendering-control positive/mutation test,
not evidence of a shipped stored-text sink. Stored literal-text round trips on
notes/tags/history belong to later slices and cannot be reported passed here.

WEB-04 parses exact CSP directives and applicable security-header matrix on
HTML success/error, redirects, JSON success/error, framework/early middleware
errors and unknown paths. Browser probes demonstrate enforced nonce/style/base/
frame/form protections; a nonced synthetic script is the positive control.
Record fresh nonce samples without retaining secret page contents. Verify
no-store, HSTS production/loopback applicability, no permissive CORS and no COEP/
subdomain-HSTS/preload widening. WEB-05 inventories routes/templates/sinks and
all enabled log/trace/artifact sinks; missing sink collection fails inconclusively.

C01/C02/Q01 tests use actual public ports as well as HTTP. A's profile has only
A's allowlisted response fields; B session, malformed/expired/revoked session,
request `actor_id`/`tenant_id`/session UUID/provenance fields and forged objects
cannot select/construct/override an actor. `ActorContext` stays frozen and cannot
deserialize through request models. Only exact trusted identity issuance site is
permitted by source and wheel gates. Remove that provenance check in a mutation
and require direct-use-case tests to fail; RLS cannot mask the missing check.

## Database and architecture extension gates

Run the existing migration/rollback suites unchanged: empty-to-head,
`000_security` and populated `004_media` upgrades through `005_identity`,
interruption/ledger failure and retry. No new upgrade point is introduced.
Retain the actual populated 004-to-005 upgrade case: legacy rows and original
columns remain unchanged, nullable external-identity/CSRF linkage stays null and
resolution fails without touch. No new empty-session-table guard or migration is
planned. Existing 000–005 checksums and the exact 005 function inventory remain
unchanged by this feature; a discovered SQL defect needs separate additive review.
Exact installed schema manifest includes new auth columns/constraints/indexes,
all seven control tables, protected capacity rows, fixed functions, owner and
grants. Runtime cannot SELECT/DML control tables or sequences, assume owner,
invoke private helpers/unknown overloads, read media, or use malformed digests,
open-ended destination/config/scope inputs or caller-supplied time/owner IDs.
Reuse and integrate actual 005 discriminated admission tests: kind bearer/allowlist,
legacy null-as-bearer, permitted_subject only on allowlist, and unique unconsumed
canonical issuer/subject. Successful unknown-subject allowlist bootstrap consumes
that one-shot admission inside finish; failing issuance rolls consumption back.
Its synthetic digest is not a bearer token. Explicit invitation_digest selects
only bearer admission, so a bad supplied token cannot fall back to allowlist;
no supplied token selects a matching valid subject admission. Known active
identity ignores supplied admission. Replayed/expired/wrong-issuer/conflicting
admissions have the same no-authority failure. No permanent allowlist/new table
or caller boolean is introduced.

Catalog ensure uses actual actor-derived tenant predicates and FORCE RLS in a
separate runtime transaction. Inspect every private SQL site and bind provenance;
run independent predicate-removal and RLS-removal mutations on A/B fixtures,
pool reuse/missing/mismatched context, wrong-tenant objects and cancellation.
Pair insertion/owner-grant/ready-mark races and failures preserve exactly one
correct catalog/grant and never mark a disabled identity ready.

Extend fail-closed source/wheel/composition checks with exact reviewed exceptions
for identity actor issuance, auth functions, public-port wiring, templates,
private SQL sites and routes. Do not simply remove health-only restrictions.
Mutation probes add an unlisted route, SQL execution site, foreign-private
import, arbitrary actor constructor, helper EXECUTE grant and media adapter;
each must fail its named gate. No worker, management API, linking, extra provider,
Android/Telegram token, sharing or destructive endpoint is registered.
